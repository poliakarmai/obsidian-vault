# Душкин Р.В. — Искусственный интеллект (2019)

Классический учебник. 7 глав, 280 стр. Автор — директор по науке Агентства ИИ, член РАИИ.

## Структура

1. **История развития** (стр. 10-47) — от Аристотеля до 2019
2. **Три столпа ИИ** (стр. 48-82) — символьные вычисления, нейросети, эволюционные алгоритмы
3. **Современное состояние** (стр. 83-154) — 10 разделов: поиск, NLP, знания, ML, распознавание, анализ данных, НЕ-факторы, экспертные системы, робототехника, многоагентные системы
4. **Философия** (стр. 155-188) — сознание, философия ИИ
5. **Мифы и опасения** (стр. 189-203)
6. **ИИ и сферы жизни** (стр. 204-252) — 16 отраслей
7. **Перспективы** (стр. 253-266)

## Ключевые концепции для Hermes

### Экспертные системы (3.8) — наша skill-архитектура

Классическая модель:
- **База знаний** → наши `skills/` (SKILL.md)
- **Рабочая память** → `memory.md` + `USER.md`
- **Машина вывода** → `skill_view()` + LLM-роутер
- **Интерфейс** → Telegram/WhatsApp/CLI

Системы поддержки принятия решений (СППР):
- Хранилище данных → наш `state.db`
- Статистический анализ → `cost-tracker`, `metrics-collector`
- Интеллектуальный анализ → `pipeline-trace`, `reflect.py`
- Модуль отчётности → `cost-weekly-report`, `vietnam-guide-monitor`
- Интерфейс аналитика/руководителя → Telegram Home

### Многоагентные системы (3.10) — наша оркестрация

- **Агенты с целями** → субагенты через `delegate_task`
- **Контроллер/координатор** → Море (главный оркестратор)
- **Аукционы/переговоры** → Cron-джобы с приоритетами
- **Роевой интеллект** → MetaClaw skill evolution (коллективное улучшение)
- **Адаптивные светофоры** → rate-limiter с динамическими порогами

Пример из книги: агенты-автобусы торгуются за продление фазы светофора. 
Аналог у нас: тенанты конкурируют за лимиты токенов через `rate_limiter`.

### НЕ-факторы (3.7) — обработка неполных знаний

4 типа неполноты знаний:
| НЕ-фактор | Пример у нас |
|-----------|-------------|
| Нечёткость | LLM-ответы без точных цифр |
| Неопределённость | Пользователь: «наверное, цена около $100» |
| Неточность | Погрешность API-датчиков |
| Недоопределённость | Провалы в `corrections.jsonl` |

**Правило из книги:** НЕ-факторы типа 1 можно извлекать автоматически. Типа 2 — нужно устранять.

### Философия (4.1-4.2)

- **Изучай естественный интеллект чтобы строить искусственный** — Душкин настаивает что инженер ИИ должен знать нейробиологию
- **Агентность = реактивность + проактивность + социальность** — совпадает с нашей моделью
- **Китайская комната vs сильный ИИ** — классический спор, книга на стороне «слабого ИИ как инструмента»

## Что применить

1. **Архитектура СППР** → структурировать наши cron-отчёты как полноценную систему поддержки решений
2. **НЕ-факторы в corrections.jsonl** → классифицировать провалы по 4 типам неполноты
3. **Аукционы агентов** → приоритизация cron-джобов по «стоимости» (важности)
4. **Изучение естественного интеллекта** → добавить в hermes-constitution принцип «изучай пользователя чтобы улучшать агента»
