# SDD через все роли — конспект доклада

## Ключевые цифры

- 100% adoption разработчиков (конец 2025)
- 150 человек в компании
- 10-летний монолит + микросервисы
- 58K ⭐ OpenSpec на GitHub
- Внедрение SDD: несколько месяцев в продакшене
- Цель: выход на L3 автономности осенью 2026

## Матрица зрелости автономности

| Уровень | Метафора | Описание |
|---------|----------|----------|
| L1 | Ручной конвейер | Чатик, copy-paste в AI |
| L2 | Экзоскелет | Локальные агенты (Claude Code, Codex), работа с артефактами |
| L3 | Облачные агенты | Агенты вне ноутбука, автономные задачи |
| L4 | Dark Factory | End-to-end без людей, термин из Японии |

Автор сейчас на L2, цель — L3 к осени. L3 компаний уже много в 2026.

## Путь к SDD

### История 1: Adoption
- Лето 2025: AI-клуб энтузиастов (15-20 чел), ресёрч стека
- Трекеры из клуба помогают адоптиться остальным
- Парное программирование: эксперт + разработчик, 1 день на реальных задачах
- 95% → остальные 5% кадровыми решениями
- Поняли: учить всех глубине харнеса избыточно → нужен платформенный слой

### История 2: Матрица зрелости
- Стратегическая сессия: каждый руководитель нарисовал свой vision
- Результат: несовместимые схемы, разные харнесы, разные скиллы
- **Вывод:** нужен единый фреймворк на всю компанию

## OpenSpec — выбранный фреймворк

Почему OpenSpec:
- **Простота** — легче всего стартовать
- **Два состояния контекста из коробки:** specs/ (AS-IS) + changes/ (инкременты)
- **Brownfield-first** — «10-летние монолиты без документации — это про нас»
- **58K звёзд**, растущий тренд

### Артефакты change (инкремента)

| Файл | Что | Кто владеет |
|------|-----|------------|
| Proposal.md | Смысл, зачем (intent) | Бизнес/продукт |
| Design.md | ADR, низкоуровневый дизайн | Разработчик |
| Task.md | Чек-лист задач (можно прервать сессию) | Агент |
| Specs (Gherkin) | Критерии приёмки | Агент генерирует |

### Жизненный цикл
```
Propose → Apply → Archive
   ↑         ↑        ↑
аналитик  разработчик  слияние в источник истины
```

Дополнительно: **Explore** — «прожарить» идею перед Propose (аналог brainstorm).

## Сквозной SDD — все роли

**Антипаттерн:** SDD только для разработчиков → два источника истины (Confluence + SDD-спеки).

**Правильно:**
```
Продукт/аналитик → Propose (намерение)
        ↓
Разработчик → Review → Apply (реализация)
        ↓
QA → Shift-left (проверка после аналитика и после разработчика)
```

### Тестирование
- Поняли что end-to-end тесты эффективнее отдавать агенту (loop engineering)
- Добавили артефакт **Test Plan** — через всю пирамиду тестирования
- Трассировка на критерии приёмки → не раздувается количество E2E тестов

### Tiny Teams
- Full-cycle инженер должен закрывать всё: аналитика, код, тесты
- Проблема: фронтендер не спроектирует БД, бэкендер не провалидирует React
- **Решение:** в plan.md разбивать задачи по ролям — apply front, apply back

### Аналитики
- Подсадили на локальный харнес раньше (задавать вопросы к коду вместо разработчиков)
- Сессии с проработкой рисков отказа от Confluence
- **Confluence для стейкхолдеров:** отдельный скилл генерирует артефакты из SDD-спек

### Gherkin vs Use Cases
- Попробовали заменить Gherkin на Use Cases → деградация качества автотестов
- **Вернулись на Gherkin**, use cases — дополнительным скиллом для просмотра

### Multi-repo → мета-репозиторий
- 2 монолита + пачка микросервисов в разных репозиториях
- Мета-репозиторий: `make clone` → все репозитории в одном месте
- `agents.md` описывает где что лежит
- Один change — сквозное изменение через N репозиториев

## Change-центричная парадигма

- Каждый коммит подписан change ID
- Трассировка: код → коммит → change → смысл
- Агент сам распутывает контекст: «что это за код? → ищу спеки → понял, расширяю»
- Свой сервис визуализации жизненного цикла (2 вечера кодинга)

## Что НЕ делать через change

- Поправить цвет кнопки — overhead
- Баг в спеке (спека правильная, агент ошибся) — не нужен новый change
- **Правило:** change нужен когда меняется спецификация/смысл

## Харнес поверх SDD

- SDD = фундамент, скиллы = надстройка
- Superpowers (TTD-часть), Agent Reach, SSH для дистрибуции скиллов
- LangFuse для сбора трейсов со всех разработчиков
- Дорожная карта: ~35% практик внедрено, остальные в процессе

## Эффекты

- Бейзлайн оценок до/после — кратное ускорение на ряде задач
- Узкое место сместилось в аналитику и product management
- Дизайнеры пока без AI (тормозят)

## Выводы Поддубного

1. **SDD — внедрять сквозным образом** (все роли, единая цепочка)
2. **Спеки = единый источник истины** (общий язык для агентов и людей)
3. **Харнес = движок производства**, на SDD-рельсах едет увереннее
4. **Не застревать на L2** — выбирать инструменты с CLI, не только IDE-плагины
